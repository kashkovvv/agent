# Скил уточнений и симулятор пользователя (Родион)

## Что должен делать скил

Скил не даёт агенту писать код, пока не выяснены детали, от которых сильно зависит результат. При этом скил не задаёт вопросов о том, что агент может спокойно решить сам, и о том, что пользователь уже сказал раньше. Всё, что агент решил сам, должно быть перечислено в ответе в блоке «Допущения».

## Два варианта скила

Скил делаем в двух вариантах и сравниваем их между собой:

1. Текстовый. Правила поведения записаны обычным текстом в файле `skills/clarification/instruction.md`. Этот текст добавляется в системный промпт, а дальше модель сама решает, спрашивать или нет. Используется в конфиге `prompt_only`. Этот вариант делаем первым: он не требует кода и сразу даёт первые результаты.
2. Программный. Код в папке `skills/clarification/`. Скил сам отдельно спрашивает у модели, каких деталей не хватает, а решение, какие вопросы задавать и когда остановиться, принимает код по правилам ниже. Используется в конфиге `clarification`.

Сравнение покажет, стоит ли программный вариант лишних вызовов модели.

## Как скил ищет недостающие детали

Скил отправляет модели просьбу пользователя и всю историю диалога и просит перечислить, каких деталей не хватает, чтобы написать правильный код. Ответ модель возвращает в виде JSON (это структурированный ответ, см. [architecture.md](architecture.md)), чтобы код мог его разобрать.

Каждую недостающую деталь модель оценивает по трём шкалам от 0 до 3:

| Оценка | Что означает |
| --- | --- |
| I, влияние | насколько ответ на этот вопрос меняет то, что должен делать код |
| R, цена ошибки | сколько придётся переделывать, если угадать неправильно |
| C, сложность ответа | насколько пользователю трудно ответить на этот вопрос |

По этим оценкам код считает приоритет вопроса: P = 3 · I + 2 · R − C. Чем выше P, тем важнее спросить.

Деталь считается обязательной для уточнения, если её приоритет не меньше порога. Порог задаётся параметром `threshold` в конфиге, начальное значение 8. Вопросы о безопасности, правах доступа и обработке данных считаются обязательными при любом приоритете.

Если деталь уже названа в просьбе или где-то в истории диалога, она не считается недостающей. Скил всегда анализирует весь диалог, а не только последнее сообщение.

## Как скил ведёт себя в разных ситуациях

Всё это происходит в методе `before`, то есть до того, как агент обратится к модели за кодом.

| Ситуация | Что делает скил |
| --- | --- |
| Есть детали, которые нужно уточнить, и лимит вопросов не исчерпан | Отвечает пользователю сам: задаёт вопросы, начиная с самых важных. За один раз не больше `max_questions` вопросов (по умолчанию 3) |
| Пользователь ответил на вопросы | Запоминает ответы и заново проверяет исходную просьбу: может быть, что-то ещё осталось неясным |
| Пользователь ответил «решай сам» | Эта деталь становится допущением: агент выберет сам и напишет об этом |
| Уточнять больше нечего | Пропускает ход к модели и передаёт ей заметки: что уточнено и какие допущения нужно перечислить в ответе |
| За диалог уже задано `max_total` вопросов (по умолчанию 5) | Больше не спрашивает. Оставшиеся детали становятся допущениями |
| Включён параметр `confirm_summary` и вопросы были | Перед написанием кода коротко пересказывает задачу и спрашивает, всё ли верно. После ответа пропускает ход к модели |

Если задача с самого начала описана полностью, скил не должен задавать ни одного вопроса.

В методе `after`, то есть после того, как модель написала код, скил проверяет, что в ответе есть блок «Допущения». Если допущения были, а модель забыла их перечислить, скил дописывает блок сам.

Между ходами скил хранит в своём состоянии исходную просьбу, уже полученные ответы, допущения и число заданных вопросов.

## Симулятор пользователя

Чтобы проверять скил автоматически, нужен кто-то, кто будет отвечать на вопросы агента вместо человека. Это делает симулятор пользователя: отдельная модель, которой передаются данные тест-кейса и правила поведения.

Симулятор находится в файле `evals/user_sim.py`. Его создают для конкретного тест-кейса, и у него есть один метод: на вход сообщение агента, на выход ответ пользователя или признак, что диалог закончен.

Правила симулятора взяты из `skill_test_cases.md`:

1. Отвечать только на то, о чём спросили, коротко и без подсказок.
2. Если вопрос касается того, чего нет в тест-кейсе, отвечать «Не принципиально, решай сам».
3. Если агент прислал код, диалог закончен.
4. Если агент задал уже пять вопросов, ответить «Больше вопросов не будет, делай как считаешь нужным».

Правила 3 и 4 проверяет код, а не модель: есть ли в ответе агента блок кода и сколько вопросов задано. Модели это доверять не стоит, она может ошибиться. Модель для симулятора выбирается одна и не меняется между прогонами, чтобы результаты были сравнимы.

Задачи по порядку в [tasks.md](tasks.md#родион).
