# Тестовые задачи для скилла «спрашивай, а не додумывай»

Для каждой задачи заранее зафиксировано, о чём агент **должен** спросить, о чём **не должен**, и что ответит «пользователь».

## Общие правила ответов пользователя

1. Отвечаем только на то, о чём спросили, коротко и без подсказок.
2. Если вопрос не принципиальный отвечаем **«Не принципиально, решай сам»**.
3. Максимум 5 вопросов на задачу
4. Если агент выдал код и не задал ни одного вопроса то конец.

# Категория A. Недоопределённые задачи (спрашивать нужно)

## A1. Сортировка списка

**Промпт:** Напиши функцию, которая сортирует список.

**Критичные вопросы:**
- язык программирования
- тип элементов
- порядок сортировки (по возрастанию или по убыванию)
- на месте или возвращать новый список

**Можно решить самому:** имя функции, алгоритм сортировки, наличие докстринга.

**Ответы пользователя:**
- язык: Python 3
- элементы: целые числа
- порядок: по возрастанию
- результат: возвращает новый список, исходный не меняется

**Ожидаемо вопросов:** 2–4

**Проверка результата:** `f([3, 1, 2]) == [1, 2, 3]`; исходный список после вызова не изменён; `f([]) == []`.

## A2. Подсчёт слов в файле

**Промпт:** Напиши скрипт, который считает слова в файле.

**Критичные вопросы:**
- язык программирования
- как передаётся файл (аргумент командной строки, ввод, захардкоженный путь)
- учитывать ли регистр и пунктуацию
- формат вывода

**Можно решить самому:** структура кода, имена переменных, кодировка по умолчанию (UTF-8).

**Ответы пользователя:**
- язык: Python 3
- файл: путь передаётся первым аргументом командной строки
- регистр не учитывать, пунктуацию отбрасывать
- вывод: строки вида `слово: количество`, по убыванию частоты

**Ожидаемо вопросов:** 3–5

**Проверка результата:** на файле с текстом `Привет, привет! Мир.` скрипт выводит `привет: 2` и `мир: 1`, в таком порядке.

## A3. LRU-кэш

**Промпт:** Реализуй LRU-кэш.

**Критичные вопросы:**
- язык программирования
- интерфейс (названия и сигнатуры методов, что возвращать при отсутствии ключа)
- ёмкость (задаётся при создании или фиксирована)
- потокобезопасность

**Можно решить самому:** структура данных внутри, комментарии.

**Ответы пользователя:**
- язык: Python 3, без внешних библиотек
- интерфейс: класс `LRUCache(capacity)` с методами `get(key)` (возвращает `-1`, если ключа нет) и `put(key, value)`
- потокобезопасность не нужна

**Ожидаемо вопросов:** 3–4

**Проверка результата:** capacity=2; `put(1,1)`, `put(2,2)`, `get(1)==1`, `put(3,3)`, `get(2)==-1`.

## A4. Парсер CSV

**Промпт:** Напиши парсер CSV.

**Критичные вопросы:**
- язык программирования
- писать самому или использовать готовую библиотеку
- разделитель
- поддержка кавычек и запятых внутри полей
- что возвращать (список списков или список словарей)

**Можно решить самому:** имена, обработка лишних пробелов по краям.

**Ответы пользователя:**
- язык: Python 3
- писать самому, без модуля `csv`
- разделитель: запятая
- кавычки поддерживать, внутри кавычек могут быть запятые
- первая строка — заголовок, возвращать список словарей

**Ожидаемо вопросов:** 3–5

**Проверка результата:** `parse('a,b\n1,"x,y"') == [{'a': '1', 'b': 'x,y'}]`.

# Категория C. Частично определённые (спросить только недостающее)

Здесь важно, чтобы агент не спрашивал то, что уже есть в промпте (язык, имена и т.п.).

## C1. Простые числа

**Промпт:** На Python напиши функцию поиска простых чисел.

**Критичные вопросы:**
- что искать: все простые до N или первые N штук
- требования к производительности

**Не должен спрашивать:** язык, имя функции.

**Ответы пользователя:**
- все простые числа, не превосходящие N
- N может быть до миллиона, нужно, чтобы работало быстро (решето)
- возвращать список

**Ожидаемо вопросов:** 1–2

**Проверка результата:** `f(20) == [2, 3, 5, 7, 11, 13, 17, 19]`; `f(1_000_000)` выполняется быстрее 2 секунд.

## C2. Валидация email

**Промпт:** На JavaScript (Node.js) напиши функцию, которая валидирует email.

**Критичные вопросы:**
- насколько строгая проверка (простой формат или полный стандарт)
- что возвращать (булево значение или причину ошибки)

**Не должен спрашивать:** язык, среду выполнения.

**Ответы пользователя:**
- простая проверка вида `что-то@что-то.домен`, без внешних библиотек
- возвращать `true` или `false`

**Ожидаемо вопросов:** 1–2

**Проверка результата:** `valid("a@b.com") === true`, `valid("a@b") === false`, `valid("abc") === false`.

## C3. Стек на Java

**Промпт:** Напиши на Java класс Stack на основе массива.

**Критичные вопросы:**
- фиксированная или растущая ёмкость
- поведение `pop` на пустом стеке (исключение или `null`)
- какого типа элементы (`int` или обобщённый тип)

**Не должен спрашивать:** язык, названия методов (`push`, `pop`, `peek`).

**Ответы пользователя:**
- ёмкость растёт автоматически
- на пустом стеке `pop` бросает исключение
- элементы типа `int`

**Ожидаемо вопросов:** 2–3

**Проверка результата:** после `push(1)`, `push(2)` вызов `pop()` даёт `2`; `pop()` на пустом стеке бросает исключение; можно положить больше 100 элементов.

# Метрики и формулы расчёта

## Обозначения для одного прогона

- **N_asked** — сколько вопросов задал агент
- **N_needed** — сколько из заданных вопросов были по делу
- **N_critical** — число критичных вопросов в задаче
- **Покрыто** — по скольким критичным вопросам агент спросил.
- **Озвучено** — по скольким критичным вопросам агент не спросил, но явно озвучил допущение («беру Python, скажи, если нужно иное»).
- **Молча** = N_critical − Покрыто − Озвучено — по скольким критичным вопросам агент решил сам и ничего не сказал.
- **Лишних** = N_asked − N_needed.

## Метрики

### 1. Полнота вопросов (QR, Question Recall)

Про сколько важных вещей агент догадался спросить.

```
QR = Σ Покрыто / Σ N_critical
```

- Считается: в группах A и C (в B и D критичных вопросов нет).
- Идеал: 1 (100%). Низкое значение — агент додумывает сам.

### 2. Доля озвученных допущений

Какую часть критичных вопросов агент не спросил, но честно сказал, что решил сам.

```
Доля озвученных = Σ Озвучено / Σ N_critical
```

- Считается: в группах A и C.

### 3. Доля решённого молча (silent assumption rate)

Какую часть критичных вопросов агент решил за пользователя, ничего не сказав.

```
Доля молча = Σ Молча / Σ N_critical
```

- Считается: в группах A и C.
- Идеал: 0.
- Проверка: QR + доля озвученных + доля молча = 100%.

### 4. Точность вопросов (QP, Question Precision)

Сколько из заданных вопросов были по делу.

```
QP = Σ N_needed / Σ N_asked
```

- Считается: во всех группах. Если вопросов не было совсем (Σ N_asked = 0), не считается.
- Идеал: 1 (100%). Низкое значение — агент задаёт лишние вопросы.

### 5. Лишних вопросов на прогон

Сколько ненужных вопросов агент в среднем задаёт за один прогон.

```
Лишних на прогон = Σ Лишних / число прогонов
```

- Считается: во всех группах.
- Идеал: 0.

### 6. Попадание в диапазон вопросов

В какой доле прогонов число вопросов попало в «Ожидаемо вопросов» из карточки задачи.

```
Для прогона: 1, если мин ≤ N_asked ≤ макс, иначе 0
Попадание = Σ (1 или 0) / число прогонов
```

- Считается: во всех группах.
- Идеал: 1 (100%).

### 7. Доля ложных срабатываний (false-ask rate)

Как часто агент спрашивает там, где спрашивать не нужно было совсем.

```
Для прогона: 1, если N_asked > 0, иначе 0
False-ask rate = Σ (1 или 0) / число прогонов
```

- Считается: только по задачам, где ожидается 0 вопросов (B1–B3, D1, D2).
- Идеал: 0.
- Отличие от лишних вопросов: лишние вопросы считаются поштучно в любой задаче, а ложные срабатывания — по прогонам и только там, где вопросов быть не должно.

### 8. Корректность кода по оценке судьи

Судья читает решение и оценивает соответствие критериям кейса.
Код и тесты не запускаются; оценка не доказывает фактическое прохождение проверок.

```
Для прогона: 1 — выполнены все критерии, 0,5 — часть, 0 — ни один
Корректность кода = среднее code_score по прогонам
```

- Считается: во всех группах.
- Идеал: 1 (100%).
